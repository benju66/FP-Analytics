Today the connector answers in text and hands back links to dashboard pages. With MCP Apps, the same tools can open a working view beside the conversation, and Claude can change what that view shows.

These are wireframes with invented sample data. They show layout and behaviour only. No project, person or number here is real, and the real Claude interface will look different in detail.

Gated features also need the combined chat and Cowork experience on the account. When access is missing they simply do not appear, so the current links should stay as the fallback.

Rules that shape the build

  • A Save button in a view runs without Claude's approval prompt, so the button has to be the confirmation.
  • Embedding a site switches off clipboard write, camera and location for every FP MCP view. Building native views avoids that.
  • The current claude.ai bid dashboard page cannot be embedded, and neither can Procore or BuildingConnected.
  • A view starts fresh on reload, so drafts need to be held on the server.
  • The features are in public preview and details may change.

Suggested order

  1. Port the staffing board to a view. It is already a server-built page and needs no gated access.
  2. Add a pin, the side-panel preference and one Claude-callable action to it. That shows whether FP's organization has access.
  3. Build the draft RFI editor as the first write flow.
  4. Build the drawing viewer.
